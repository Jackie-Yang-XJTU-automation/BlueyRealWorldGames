# 可玩游戏设计模式

本文是 BlueyRealWorldGames 所有深度可玩游戏的唯一设计规范。可玩游戏的目标不是把孩子留在屏幕上，而是让 App 成为现实亲子游戏的主持器：发任务、制造意外、记录节奏，真正的游戏发生在客厅、院子、公园和家人之间。

## 设计原则

- **剧情有根**：每个游戏必须先参考对应剧集资料，优先阅读 `docs/superpowers/data/SxEy-*.md`，必要时再查 `docs/superpowers/scripts/SxEy-*.md`。
- **现实可玩**：任务必须能在真实家庭场景中完成，材料常见、动作安全、家长能理解并参与。
- **Bluey 味道**：保留剧集里的冲突、笑点和情感核心，例如轮流、守规则、合作、家长夸张表演、孩子主导想象。
- **屏幕退后**：App 只做主持和节奏控制，孩子不需要长时间盯着屏幕操作。
- **家长小抄**：运行页首先是给家长看的陪玩提词器。家长不一定熟悉剧情，文案要能让家长立刻读给孩子听，并知道下一步怎么演。
- **触屏现场优先**：默认使用场景是家长拿手机在客厅、院子或户外主持游戏。移动端触摸体验是主体验，桌面只是辅助预览。
- **阶梯推进**：任务卡必须有难度和剧情递进，不允许只是随机动作列表。

## 家长主持小抄标准

把自己当成一个偶尔看 Bluey、周末带 4 岁孩子反复玩了 100 次的家长来评审每个页面。一个可玩游戏运行页必须优先满足：

1. **一句话开演**：进入或开始后，家长能直接照着说一句话，把孩子带进角色，例如“我们现在是医院，爸爸是病人，你先检查哪里痛。”
2. **当前任务唯一主角**：第一屏只突出当前任务、必要动作、安全提醒、暂停和结束。不要让星星、排行榜、完整任务树和系统徽章抢走注意力。
3. **现实动作比屏幕操作重要**：按钮是主持辅助，不是孩子要盯着玩的游戏控件。每个按钮都应对应现实动作、角色扮演或家长提示。
4. **结算夸亲子表现**：结束时优先反馈轮流、合作、感谢、勇敢、安全完成、想象力和角色投入；分数/排名只能作为附属记录。
5. **生活场景优先选游戏**：首页和推荐应帮助家长按真实处境选择：家里安静玩、消耗体力、爸妈一起演、5 分钟快玩、不用材料、睡前可玩。
6. **游戏卡像陪玩便签**：卡片优先告诉家长“孩子为什么会想玩、需要准备什么、适合几个人和哪里玩”，难度、集数和分类只能做辅助信息。
7. **随机事件像插曲**：事件弹窗要短、轻、可演，不像系统警报。它应该制造意外惊喜，而不是让家长停下来读一大段规则。

禁止回退：
- 不把运行页做成分数面板、成就系统或完整任务树总览。
- 不要求孩子持续看屏幕才能玩。
- 不用“完成第 X 阶段获得 Y 分”替代可说出口的主持词。
- 不为了展示 Bluey 剧情资料而增加家长现场阅读负担。
- 不把首页做成筛选器优先的数据库；筛选可以存在，但不应压过“现在开哪一局”的救场入口。

## 触屏交互和动效原则

可玩游戏发生在现实空间里，因此 UI 动效必须服务于手机现场，而不是桌面网页展示。

- **家长主持优先**：可玩游戏运行页首先服务拿手机的家长。第一屏要让家长立刻知道“现在带孩子做什么、怎么安全做、如何暂停/结束”，不要默认展示完整系统面板。
- **不依赖 hover**：`hover` 只能作为桌面增强，不能承载主要趣味、状态变化、可点击暗示或玩法反馈。
- **触屏等价优先**：任何重要动效都必须在手机上有等价体验，例如按下反馈、滚动聚焦、卡片入场、收藏弹跳、任务盖章、随机事件弹出。
- **滚动聚焦要克制**：列表可使用“视口中心卡片轻微聚焦”，但一次只突出一张，幅度小，不让页面跳动。
- **现场可读优先**：手机户外单手持握时也要看清核心信息；装饰性文字、无含义徽章和只为桌面 hover 服务的元素应删除。
- **系统信息退后**：星星、排行榜、分数拆解和完整五级任务树属于记录层，优先放在结算、暂停或折叠区；运行中只突出当前任务和必要动作。
- **验证看真实手势**：UI 改动不仅看 390px 静态截图，还要检查滚动、点按、暂停、误触、reduced motion 和 console error。

## 通用玩法骨架

每个深度可玩游戏都由两种核心内容驱动：

1. **任务卡片**：主线玩法。它告诉玩家现在要在现实中完成什么动作、协作或角色扮演。
2. **随机事件**：剧情扰动。它让游戏像 Bluey 剧集一样出现意外、笑点和临时规则变化。

运行流程统一为：

```text
准备说明 → 开始倒计时 → 任务卡推进
                 ↓
          随机事件穿插
                 ↓
暂停/继续/结束确认 → 结算或庆祝
```

技术实现仍遵守现有架构：

- 数据层：`src/data/*Tasks.ts` 和 `src/data/*Events.ts`
- 逻辑层：`src/hooks/use*Game.ts`
- 页面层：`src/pages/*Page.tsx`
- 共用组件：`CountdownOverlay`、`CommandPanel`、`TaskLadderPanel`、`RandomEventPopup`、`FaultPopup`、`GameTimer`、`Leaderboard`

## 阶梯任务卡

每个游戏默认使用 5 级任务阶梯。名称可以贴合具体游戏改写，但职责不能变。

| 级别 | 目的 | 设计方式 |
|------|------|----------|
| 第1关：入戏热身 | 让孩子理解核心规则 | 动作简单、时长短、成功率高 |
| 第2关：掌握规则 | 强化本游戏最重要的约束 | 加入轮流、轻重、边界、角色职责 |
| 第3关：协作升级 | 从单人动作变成亲子配合 | 接力、救援、喊名字、家长参与 |
| 第4关：剧情冲突 | 引入剧集里的麻烦 | 爸爸捣乱、机器故障、规则变难、奖品诱惑 |
| 第5关：高潮挑战 | 形成一轮完整 finale | 全家合作完成明确目标，然后庆祝或结算 |

任务卡文案要求：

- 句子短，孩子能听懂，家长能立刻执行。
- 每张卡只传达一件事。
- 每张任务卡应提供 `hostPrompt`，写成家长能直接读给孩子听的一句话；运行态优先展示 `hostPrompt`，`description` 只补充怎么做。
- 明确现实动作、次数、时间或完成条件。
- 不设计危险动作，不鼓励奔跑碰撞、攀爬家具、抢夺物品或羞辱玩家。
- 不直接复述剧情台词，改成适合家庭现实游戏的提示。
- 优先使用“对孩子说”的主持口吻，少用系统术语、积分术语和开发者视角描述。

## 随机事件

随机事件必须服务于剧情和现实互动，分三类混合使用：

- **剧情事件**：来自对应剧集的冲突或笑点，例如爸爸抢木琴、气球飘走、机器人短路、云影来了、爪子故障。
- **规则变化**：临时改变玩法方式，例如慢动作、单手、只能轻轻碰、静音、换角色、救援。
- **亲子互动**：鼓励家人连接，例如击掌、拥抱、轮流、家长夸张表演、孩子指挥、全家欢呼。

随机事件文案要求：

- 事件持续时间短，通常 6-15 秒。
- 不打断核心玩法太久。
- 失败也要好笑，不惩罚孩子。
- 户外游戏要考虑天气、空间和视线；室内游戏要提醒慢走、轻碰、避开家具。

## 剧情适配标准

设计每个新游戏前，先写清四件事：

1. **剧集锚点**：这集最核心的游戏规则、冲突和情感是什么。
2. **现实玩法**：家庭实际需要哪些人、空间和材料。
3. **App 角色**：App 是裁判、主持、计时器、事件牌、遥控器还是结果判定器。
4. **安全边界**：哪些动作必须降级、替换或明确提醒。

允许做现实化改编。比如剧中爸爸用风扇和吹叶机把气球难度拉满，App 里可以改成“气球飘到安全线外，大家慢慢回到空旷区域”，保留笑点但移除风险。

## 实现检查清单

新增或重做可玩游戏时，必须满足：

- 已阅读对应 `docs/superpowers/data/` 剧情摘要。
- 已把目标用户当作“拿手机主持的家长”，而不是孩子独立操作。
- `src/data/*Tasks.ts` 中任务卡是 5 级阶梯设计。
- 每张任务卡都提供可直接念出口的 `hostPrompt`。
- `src/data/*Events.ts` 中随机事件至少覆盖剧情事件、规则变化、亲子互动。
- 页面使用开始倒计时、暂停/继续、结束确认。
- 主线任务通过 `CommandPanel`、`TaskLadderPanel` 或等价任务卡组件展示；任务可加入轻量完成条件，防止刚开局连续误触盖章。
- 随机事件通过 `useRandomEvent` 或同等 hook 调度。
- 游戏结束条件、胜利条件或庆祝条件清晰。
- 所有动作符合 3-8 岁儿童现实亲子游戏安全性。
- App 不要求长时间盯屏，不依赖网络，不收集个人信息。
- 运行态第一屏没有默认展示空排行榜、分数说明、完整五级任务树或大量系统徽章。
- 结算文案优先表扬亲子互动和现实完成，而不是只强调星星、排名或输赢。

## 2026-06-12 候选评估记录

本轮新增游戏从医院、魔法雕像商店、假装烧烤、骑马游戏和酒店中筛选。最终选择 **医院** 与 **假装烧烤**：

- **医院**：室内安全、角色分工清晰，Doctor Bluey、Nurse Bingo、Telemachus、X 光、猫/老鼠/奶酪治疗都能自然转成任务卡和随机事件。
- **假装烧烤**：道具常见、运动强度低，Bingo 找彩椒与“做饭的人也要被感谢”的情感核心适合真实亲子协作。
- **暂缓魔法雕像商店**：玩法有趣，但冻结/移动与魔法木琴重叠度较高。
- **暂缓骑马游戏**：身体接触和追逐更多，需要更细的安全降级。
- **暂缓酒店**：可玩性高，适合作为下一批角色扮演游戏候选。
